# QA and Repair

Open every generated image and check it against the plan, current character package, selected style contract, and output requirements. A page is not PASS because it is attractive; it must communicate the intended source-grounded job.

## Priority order

1. Character identity and fixed traits.
2. Source meaning, exact text, facts, and relationships.
3. Pixel construction and selected style contract.
4. Layout, reading order, whitespace, and character footprint.
5. Watermark, filename, dimensions, and saved path.

## Shared checks

- [ ] Current character is `confirmed`, and the clean anchor, bust, optional sheet, and spec were used.
- [ ] Face, hair/head shape, silhouette, proportion, outfit, markings, and signature accessories match.
- [ ] The image is HD retro pixel art constructed from pixel clusters, not filtered anime, 3D, or chunky 8-bit.
- [ ] One image has one communication job and a traceable source anchor.
- [ ] No invented labels, facts, charts, dates, quotes, or unrelated props appear.
- [ ] Exact text is legible and matches the plan; no paragraph is squeezed into the image.
- [ ] The character is informative when present, with the declared binding and enough text clearance.
- [ ] No watermark was generated by the model; the final watermark comes from the current spec.

## Article checks

- [ ] There is one cover and the body count reflects distinct visual beats.
- [ ] Cover uses the warm cover contract; non-cover images use one shared body look.
- [ ] A scene has a readable action and result; a process/comparison/checklist has readable structure.
- [ ] The first passing body image is used as the look-lock for later body images.
- [ ] Thumbnail view still preserves the character and central idea.

## Card checks

- [ ] Each page has one job, clear top-to-bottom reading order, and source-grounded modules.
- [ ] Multi-card cover/CTA decisions are justified by the source or user request.
- [ ] Frame, paper, typography roles, panel lines, pixel density, and accent family match the series master.
- [ ] Tables, flows, comparisons, and trees use `none` when a character would be decorative.
- [ ] Card count is content-driven, no more than nine unless explicitly overridden.

## Decision and repair

Use `REVISE` for a local label, crop, prop, spacing, or watermark issue. Use `REGENERATE` for identity drift, wrong source meaning, wrong grammar, wrong style contract, or a broken layout. Preserve all accepted pages and repair only the failing page.

Use direct repair clauses:

```text
IDENTITY DRIFT: Restore the exact confirmed face, hair/head shape, signature silhouette,
fixed outfit, markings, proportions, and accessories. Do not copy the style reference character.

TOO POLISHED: Keep the HD pixel construction but make pixel clusters, stair-stepped edges,
grouped shading, and controlled outlines more visible. Do not turn it into vector or 3D art.

TOO DENSE: Remove unrelated props, increase margins, and restore the declared reading order.
Keep every source-grounded module and do not shrink the text.

TOO GENERIC: Tie the scene directly to [source anchor] using [specific action and prop].
Remove decorative objects that do not explain the job.

TEXT ERROR: Render only the exact text manifest below. Remove invented words and split the
page if the required text cannot remain readable.

CHARACTER DECORATIVE: Remove the character or bind the hands, gaze, prop, or position to
the declared module so the character performs an information action.
```

After repair, rerun the relevant checks and then perform one series-level comparison. If the same constraint keeps failing, change strategy or report the unresolved issue; never delete constraints and call the output PASS.

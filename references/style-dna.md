# 视觉 DNA

所有用户、所有角色共用。身份来自**当前角色**；画风来自高清像素规则 + 捆绑画风锁。

## 共同

- 高清像素：颗粒细，有轻微体积和抖动阴影。不是 8-bit 大格子、不是简笔画、不是 3D 盲盒、不是写实摄影。
- 当前角色永远同一套记忆点（神态、剪影、标志色/花纹/服装）。角色可以是人、宠物、吉祥物、表情包或品牌 IP，不必须是真人。
- 水印：右下角，小而不抢眼，文案来自当前角色 `character-spec` 的 `watermark`。**排版叠加，禁止让 AI 画。**
- 一张图一个观点。本套里每张职责不同，不要两张图讲同一件事。
- **角色不要撑满画面**：清单/介绍页里人只占格子里的一小块，能用文字/表格/箭头/图标说清就不必每格都有人；演戏时主体约 40%–60%，留白给物件和字。
- 有字时：**标签贴在对应物件正下方或物件上**，图文成对。不要左边一列字、右边一个大人。图内中文按 visual plan 逐字来，不要同义改写。可选项写成 `A / B / C`。
- 图内文字写进 prompt，按这一张需要：
  - 演戏 / 一个观点：2–6 字贴在物件上，能不加就不加
  - 封面 / 知识卡：短句，见卡片预算
  - 列步骤 / 清点成品：编号短句 + 小图标成对，见 `explainer-workflow.md`
- 水印永远后盖。平台自动水印（如豆包）不管。

身份参考：**出图前必须打开当前角色包并对照全部可用资产**（见下）。冲突时再按优先级裁决。画风锁不能盖过「这是谁」。

抽象知识怎么入画：先读 `concept-visual-language.md`，写短 visual plan 再拼 prompt。

## 角色包全量参照（生图硬规则）

`confirmed` 角色出图时，身份源不是「只看一张全身图」，而是整包：

| 资产 | 必须？ | 用来锁什么 |
|---|---|---|
| `character-reference-clean.png` | 必须 | 全身比例、站姿剪影、整套服装 |
| `character-bust.png` | 必须 | 脸、神态、发型近景、头配件 |
| `character-sheet.png` | 有则必须用 | 三视图角度、配饰特写、配色色板 |
| `character-spec.md` | 必须 | 文字记忆点、允许/禁止改、水印 |

生图调用时：把 **clean + bust +（若有）sheet** 一并作为 identity 参考图传入；并把 spec 里的签名剪影/记忆点写成短 Character Lock（勿整份粘贴）。  
禁止只塞一张全身就开画。

## 画风锁

捆绑参考图只负责「像素长什么样 / 版式气质」，不负责「用户是谁」。

| 用途 | 路径 | 怎么用 |
|---|---|---|
| 角色像素密度 | `assets/character/jinger-pixel-bust.png` + `jinger-pixel-fullbody.png` | 创建/转换角色、以及非示范身份出图时传入，只学颗粒、描边、上色 |
| 长文封面场景气质 | `assets/style-lock/warm-pixel-scene-16x9.png` | 只给 16:9 **封面**学暖色简单场景 |
| 长文正文画风气质 | `assets/style-lock/article-body-editorial-16x9.png` | 只给 16:9 **正文**学：米白底 + 像素边框/UI 模块 + 信息图气质；**不要**复制图中样例角色身份 |
| 知识卡编辑气质 | `assets/style-lock/knowledge-card-editorial-3x4.png` | 只给 3:4 知识卡学：纯色底 + RPG UI 模块 + 讲解者；**不要**把样例角色身份盖过当前角色 |
| 示范设定（给人看，不默认启用） | `examples/jinger/` | 作者示范；开源用户不要设成当前角色 |

规则：

- 当前角色**不是**这套示范身份 → 只学画风，不要复制画风锁图里那个人的脸、帽、衣服。
- 当前角色**就是**这套示范身份（仅作者本地已确认）→ 身份和画风都可以用这些图。
- 三视图等 sheet 资产属于**当前角色身份**，不是画风锁。

## 长文 16:9

一套必须同时有：

1. 封面 / 主题背景 × 1
2. 正文解释图 × 按信息密度（见 `article-workflow.md`）

| 用途 | 背景 | 密度 |
|---|---|---|
| 封面 / 主题 | 暖色简单像素场景：奶油纸 / 浅木桌 / 软木板，可加深棕像素细边框；桌上 1–3 小物件。**底色可与正文不同，相同也可以** | 可稍满：人物 + 少量信息块 + 桌面 |
| 正文解释 | 对齐 `article-body-editorial-16x9.png`：米白/暖底 + 像素细边框/UI 模块感；同一篇文章的全部正文图必须统一底色、边框、像素风格。普通观点也可迷你剧场，但颗粒与边框气质跟正文锁一致；列步骤/清点/对比走说明图 | 物件 1–3；演戏时主体约 50%–65%；说明图字大、人小 |

禁止：写实风景、完整大房间巡游、霓虹 HUD、Vox 黄黑拼贴、PPT SmartArt、正文图塞成白皮书海报。  
禁止：同一篇正文图里混用完全不同的底色/边框（例如一张奶油纸、一张深绿 RPG）。

**流程拆解**（解释一个机制时）：3–5 节点；角色可分身，每个分身都在做事；从左到右，要透气。  
**核心动作**（迷你剧场）：一个角色 + 一个核心物件 + 一个动作 + 一个可见结果。角色必须参与核心关系，去掉角色图就不成立。  
**说明图清单**：信息设计优先，角色可选；见 `explainer-workflow.md`。

若这一张的内容就是在列步骤 / 清点成品，把 `explainer-workflow.md` 里的排法写进 prompt，不要空荡荡只站两个人，也不要每格都塞一个大人。

## 知识卡片 3:4

- 画幅 3:4。流水线见 `card-workflow.md`（内容分析→版式→风格→角色 edit→生图→可选二期排字）。
- 气质对齐 `knowledge-card-editorial-3x4.png`：**几乎纯色**暖米白底 + RPG/像素 UI；信息有密度；不是房间剧场。
- 角色是讲解者；全身/半身/多小分身按排版与文字互动选择，不默认某一种；占位通常约 1/4～1/3。
- 身份优先 edit-from-package；知识点来自原文；禁止降质求通。
- 英文像素标题用于主标题/关键词；说明用短句。步骤/对比见 `card-templates.md`。
- 禁止：HTML 杂志贴图、复杂房间、Vox 拼贴、深色 Game Boy 整屏、PPT SmartArt、像素滤镜假像素

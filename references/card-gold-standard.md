# 知识卡黄金样张规范

本文件把两类已通过审美验证的 3:4 卡片提炼成 image-2 可执行的视觉语法：

- `03-concept.png`：高密度概念解释页
- `04-folder.png`：中密度结构讲解页

作者本地存在这两张图时，把它们作为当前系列的 **双重 LOOK LOCK**；开源用户不依赖这些本地路径，先使用 `assets/style-lock/knowledge-card-editorial-3x4.png`，首张通过后立即把通过图设为本系列主 LOOK LOCK。

黄金样张只锁版式气质，不替代当前用户角色包。身份冲突时，`character-bust.png` / `character-reference-clean.png` / spec 永远优先。

## 一、两张图为什么像同一套

### 1. 画布与外框

- 固定 3:4 竖版。
- 全页只有一个连续外框；外框贴近画布边缘，四角是大圆角的阶梯像素切角。
- 外框采用深咖外线 + 中棕内线 + 一条浅色高光，形成轻微 RPG 窗口厚度。
- 页面内部不再套第二个整页大框；模块只用细实线、虚线或浅底分组。
- 同一系列禁止每页换边框：不能一页双线、一页金属框、一页卷轴、一页无框。

### 2. 背景与色盘

- 画布主体是近乎纯色的暖米白 / 象牙纸面；允许极轻纸张颗粒，不允许明显渐变、光晕或场景背景。
- 结构色统一为深咖 / 近黑棕，用于标题、正文、外框、连接线。
- 主强调色是一组低饱和琥珀金 / 蜂蜜黄，用于文件夹、节点、星光、序号或少量关键词。
- 角色固有的发色、服装色不计入版式强调色。
- 内容确有语义时，可用一个极小面积的辅助语义色（例如勾选绿、提示粉）；总面积应低于画面约 3%，不能形成第二套主色盘。

### 3. 字体分工

- 主标题用粗像素展示字，承担第一视觉层级。
- 中文正文用清晰、紧凑、非像素化的黑体 / 无衬线字；不要把所有中文都画成粗像素字。
- 模块标题用加粗正文体或小号像素编号；正文说明用常规字重。
- 一页最多三档主要字级：主标题、模块标题、正文说明。页脚可作为第四档，但必须弱化。
- 主标题约占页面高度 7%–12%；正文在缩略图中仍应形成清楚行块，不能糊成装饰线。

### 4. 信息模块

- 页面不是相同卡片的机械网格，而是由 3–5 个内容模块组成的纵向阅读路径。
- 每个模块至少包含“模块标题 + 对应图标/物件 + 1–3 行短解释”中的两项；重要模块三项齐全。
- 图标与文字一一绑定：文件夹对应目录，靶心对应触发条件，清单对应流程，箱子对应材料。
- 连接线只表达真实结构关系；装饰星光只放在标题或结论附近，不散落全页。
- 模块内边距保持宽松；模块之间的间距大于模块内部文字间距，从而自然形成分组。

### 5. 角色视觉权重

- 不用“角色占页面高度多少”单独判断大小；全身角色可以较高，只要足够窄、位于保留列、没有压字。
- 单个全身讲解者可高约画布 30%–42%，但宽度通常不超过画布 16%–18%，实际涂色占地约 5%–8%。
- 单个半身讲解者通常高约 14%–24%，实际占地约 4%–7%。
- 多个小分身可出现 2–4 次，每个绑定不同模块；所有角色实例合计涂色占地建议不超过画布约 18%。
- 角色视觉权重必须低于最大信息结构；不得覆盖文字、改变正文列宽或迫使正文缩小。
- 多角色不乱的条件：同一脸和服装、同一像素密度、每个实例处在独立模块、动作不同、轮廓不互相碰撞。

## 二、03-concept 的结构拆解

页面任务：在一张卡中完成“定义 → 拆解 → 对比 → 一句话结论 → 典型结构”。

阅读顺序：

1. 顶部大标题 `SKILL 是什么？`
2. 两行引入解释
3. 主说明文件夹 + 可选材料
4. 三个并列组成模块
5. “没有 Skill / 有了 Skill”对比带
6. 一句话定义
7. 页脚典型结构

它高密度但不乱的原因：

- 信息被切成五个横向带，每一带只回答一个子问题。
- 三个组成模块尺寸一致，但对比带、结论带和页脚采用不同结构，避免“六张一样的卡”。
- 顶部全身角色占窄右栏；中部两个半身角色分别属于左右对比；底部半身角色抱住结论手册。角色不是重复贴纸，而是四个不同信息动作。
- 大标题、深色横条、VS、粉色下划线形成少量强锚点；读者可以先扫结构，再读正文。
- 角色和模块之间有明确物理关系：指示、操作电脑、抱住手册；没有人物悬浮在无关空白处。

适用内容：定义、框架、复杂概念总览、一个术语的多层解释。

对应版式模具：`definition-dashboard`。

## 三、04-folder 的结构拆解

页面任务：解释一个层级结构，并给出可执行建议。

阅读顺序：

1. 左上大标题
2. 根节点 `SKILL.md 入口`
3. 三条树状分支
4. 每条分支右侧的一句职责说明
5. 左下使用建议
6. 右下文件盒 + 讲解角色

它中密度但不空的原因：

- 左侧树线是主视觉骨架，信息模块沿树线自然下行，不需要额外大箭头。
- 每个分支采用“文件夹名牌 + 图标说明框”的成对结构，扫一眼就能完成左右匹配。
- 页面下方用一个较大的建议框收束，避免上半页只有目录、下半页只有人物。
- 角色虽然是全身，但被锁在右下保留列，窄而不压字；指示棒直接指向结构，文件盒补充“内容围绕入口展开”的隐喻。
- 大片米白留白不是空洞，而是在树状结构、建议框和角色之间建立清楚边界。

适用内容：文件树、系统架构、层级关系、目录说明、流程分支。

对应版式模具：`architecture-tree`。

## 四、固定语法与可变语法

同一系列必须固定：

- 3:4 画布
- 连续圆角像素外框
- 暖米白背景
- 深咖结构色 + 琥珀金主强调色
- 像素主标题 + 清晰中文正文
- 面板描边、连接线、图标描边的像素密度
- 当前角色的脸、发型、服装、配件

每页可以变化：

- 模块数量和结构
- 角色是否出场、全身/半身/多小分身
- 图标和视觉隐喻
- 内容密度（高密度 dashboard / 中密度 tree / 低密度 CTA）
- 一条必要的语义辅助色

## 五、image-2 生成策略

### 首张卡

1. 传当前角色包作为身份参考。
2. 传 `assets/style-lock/knowledge-card-editorial-3x4.png` 作为版式气质参考。
3. Prompt 明确区分：角色包锁身份；style lock 只锁外框、背景、字级、面板、密度。
4. 先保住信息结构和中文字，再检查角色。

### 系列续图

1. 把已通过的首张卡作为主 LOOK LOCK。
2. 若有第二张不同结构但同风格的通过图，一并作为辅助 LOOK LOCK。
3. 当前作者项目中，优先使用 `03-concept.png` + `04-folder.png` 双重 LOOK LOCK。
4. 要求复制视觉语法，不复制具体页面内容或角色姿势。
5. 若多参考编辑不稳定，先用 LOOK LOCK 生成无角色/弱角色底板，再以当前角色 bust/clean 单目标 edit 进入保留位。

## 六、生成前视觉合同

每张 shot list 增加：

```text
LOOK LOCK: first-card | approved-card paths
FRAME CONTRACT: continuous rounded pixel frame, same three-tone stroke
SURFACE CONTRACT: flat warm ivory, subtle paper grain only
TYPE CONTRACT: pixel display title + clean readable Chinese sans body
PANEL CONTRACT: thin cocoa pixel lines, no glossy cards, no random shadows
DENSITY BAND: high | medium | low
CHARACTER SLOT: none | reserved column | module corner | multi-module
CHARACTER FOOTPRINT: estimated painted area percentage, not height alone
CHARACTER BINDINGS: each instance -> exact module/action
```

## 七、QA 判定

单张 PASS 必须满足：

- 外框连续，四角、描边层数和系列已通过图一致。
- 背景是同一暖米白表面，没有新场景、渐变或大色块。
- 标题、模块标题、正文的字级角色清楚，不是全页粗像素字。
- 3–5 个信息模块有明确阅读顺序；至少一个结论/建议/定义收束。
- 图标、线条、角色动作都能对应具体文字。
- 角色占地未压过信息结构；多角色各自在独立模块且总视觉权重受控。
- 缩略图先看见主题与结构，放大后才阅读解释句。

系列 PASS 还必须满足：

- 并排看时外框、底色、字体分工、线条和图标像同一本书。
- 角色身份一致，但姿势不机械重复。
- 不同页面使用不同内容结构，不是固定模板机械换字。
- 任何一页都不能因角色变大而牺牲文字密度。

# 知识卡 · 版式系统（Layout System）

固定信息设计规则 + **按内容类型可变的版式**。  
要的是：固定 Style + 可变 Layout；不是「固定一张模板换字」。

流水线位置：CONTENT ANALYZER 之后 → LAYOUT ENGINE（本文件）→ STYLE → CHARACTER → IMAGE-2。

## 通用层级（单卡可裁剪，但不要空）

1. **HERO TITLE** — 最强；英文关键词可用大号复古像素字  
2. **INTRO / CORE IDEA** — 标题下 1–2 句（来自原文紧缩）  
3. **MAIN MODULES** — 1–5 块；每块尽量有「短标题 + 一句说明/关系」，不要只有两字碎标签  
4. **CHARACTER INTERACTION** — 讲解位；全身或半身按占位选（见角色系统）  
5. **KEY TAKEAWAY** — 结论框  
6. **MICRO DETAILS** — 箭头/文件夹/UI，不得抢信息  

留白要故意留。角色不要压关键文字。四边干净边距。  
信息密度对齐气质锁与合格样例：**禁止三行字 + 巨大角色。**

编辑式知识卡的质量基线：标题先回答问题，随后用 3–6 个可扫读模块说明，最后用结论或行动框收束；每个图标、箭头和角色动作都要对应一个文字概念。学气质锁与 `card-gold-standard.md` 时，只学边框/纸面/字体分工/模块关系/留白/角色 footprint，**不要复制样例角色脸、文字或姿势**。

### 稳定栅格

- 3:4 画面四边保留约 3%–5% 安全边距，所有内容待在同一连续外框内。
- 先按纵向 band 切出标题、主结构、结论、页脚，再在 band 内分栏；禁止边生成边找空位塞人。
- 模块间距必须大于模块内部行距；同级面板等宽、等高或有明确比例关系。
- 角色槽位在排字前确定，文字区不能为了人物临时缩小。

## 版式模具库（选题先进模具，再填内容）

多卡系列默认从下面选一套模具；不要每张从零发明构图。

| 模具 ID | 什么时候用 | 槽位结构 |
|---|---|---|
| `cover-hook` | 封面/钩子 | 大标题 + 短副标题/banner + 角色半身表情或手持主题物（可较大一点） |
| `definition-dashboard` | 定义、框架总览、一个概念的组成 | 顶部定义区 → 3 个并列模块 → 对比带 → 一句话结论 → 结构页脚；角色可在不同 band 内用 2–4 个小分身，各自绑定模块 |
| `architecture-tree` | 文件夹、系统结构、层级关系 | 顶标题 → 根节点 → 纵向树线与 3–5 个分支 → 每行配对说明 → 底部建议框；可在右下保留窄全身讲解列 |
| `qa-metaphor` | 概念解释、易误解点 | 顶标题 → 左问/右答对白 → **中央隐喻物件** → 底结论 |
| `wrong-right-tips` | 对比、惯例、对错 | 顶判断句 → 中段错/对双栏（表或模块）→ 底 Tips + 可选半身讲解者 |
| `two-panel` | 故事引入、冲突→议题 | 上格冲突对白 → 下格引出今日要讲什么 |
| `steps-flow` | 步骤、流程 | 编号 ①②③ + 短句；角色可选，出场须指向某一步 |
| `cta` | 末页行动 | 短行动句 + 递出 CTA 模块；全身/半身皆可 |

页型标签（cover / pain / concept…）见 `card-templates.md`，可与上表模具组合（例如 concept + `qa-metaphor`）。

## 按内容类型选型（LAYOUT ADAPTATION）

| 类型 | 版式 |
|---|---|
| concept 概念解释 | 中心定义 + 支撑模块 |
| comparison 对比 | 双栏 / 对切 VS |
| process 流程 | 编号流程 + 方向箭头 |
| framework 框架 | 分层卡片 / 节点 / 模块块 |
| tutorial 教程 | 顺序编号分镜 |
| list 清单 | 带图标叠卡 |
| timeline 时间线 | 纵/横时间轴 |
| cause-effect 因果 | 节点 + 箭头 |
| architecture 技术结构 | 文件夹树 / 文件 / 连接器（可旁注短说明） |
| abstract 抽象 | 强隐喻 + 角色互动 |

禁止强行每篇同一模板。

## 多卡系列 vs 单卡深讲

- **多卡**：每张一个主问题；仍要标题→模块（含短说明）→讲解→结论感。不是越少字越好。  
- **单卡深讲**：4–7 块，对齐气质锁密度。  

页型标签见 `card-templates.md`；构图按上表。

## 角色占位与版式一起定

Layout 决定信息区形状后，再选 `none` / bust / fullbody / multi-mini：  
哪一种更利于指着模块、又不挤爆文字区——就用哪一种；若模块本身已经讲清楚，就用 `none`。详见 `card-character-system.md`。

不要用角色页面高度作为唯一尺寸规则。全身角色可高但必须窄、固定在预留列；多个小角色必须各自在一个 band/模块内，总着色面积仍低于信息区。详见 `card-gold-standard.md`。

# 知识卡 · 角色系统（Character System）

知识卡上的角色 = **视觉讲解者**，不是贴在角落的装饰贴纸。

身份仍来自当前 `confirmed` 角色包，且必须**全量参照**：

- `character-reference-clean.png`（全身）
- `character-bust.png`（半身脸/发型）
- `character-sheet.png`（若有：三视图/配饰/色板）
- `character-spec.md`（文字记忆点）

禁止只拿一张全身开画。出图后过 `qa-checklist.md` 的「角色包对照审核」。

## Identity Lock

- 脸、发型、比例、签名服装/配饰、整体气质与参考图一致  
- 禁止重设计成通用二次元、换装到认不出、改比例  
- 系列里必须是「同一个 IP 吉祥物反复出场」

提示词里写清：以用户角色参考图为 **PRIMARY and AUTHORITATIVE** 身份源。

## 互动（CHARACTER INTERACTION）

角色必须**演示 / 讲解 / 对比 / 操作 / 递出结论**，例如：

- 捧着标了关键概念的文件夹或 `SKILL.md`  
- 指向图示、连接两条概念  
- 用笔记本演示流程  
- 举着清单、坐在双栏对比旁  
- 对结论框做出反应  

禁止：

- 永远站在右上角抱电脑的同一pose  
- 呆站在文字旁当吉祥物  
- 只贴一张半身在空白边  

## 体量（静儿硬偏好）

- **单次出场**：大约占画面 **1/4～1/3**，字与模块是主角  
- **多处分身讲解**（对齐样例）：每个分身更小，分布在模块里，总面积仍不压过文字  
- 禁止半身/全身撑满画面  

## 与长文的区别

- 长文迷你剧场：角色常常是戏的中心  
- 知识卡：信息架构是中心，角色是讲解员

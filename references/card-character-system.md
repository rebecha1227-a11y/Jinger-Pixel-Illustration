# 知识卡 · 角色系统（Character System）

知识卡上的角色 = **可选的视觉讲解者**，不是每页必须出现的装饰贴纸。信息结构已经自洽时，角色应当省略。

## 加载角色包（必须）

当前 `confirmed` 包全量参照：

| 资产 | 用途 |
|---|---|
| `character-reference-clean.png` | 全身比例、整套服装、剪影 |
| `character-bust.png` | 脸、发型近景、头配件（裁决脸/发） |
| `character-sheet.png`（若有） | 三视图、配饰特写、配色 |
| `character-spec.md` | 签名剪影、允许/禁止改、水印 |

禁止只塞一张图就开画。出图后过 `qa-checklist.md`「角色包对照审核」。

## 一致性：优先「在包图上改」，少「从零重画」

目标：同一张脸、同一套头发、同一身衣服反复出场。

推荐调用方式（按稳到险）：

1. **edit-from-package（默认）**  
   以 `bust` 或 `clean` 为输入图，prompt 只改：姿势、手部动作、朝向、轻微表情、手持道具、放入卡片版式。  
   明确写：`Keep face, hair, outfit identical to the reference. Only change pose and props.`
2. **分步**  
   先出信息图底板（框/箭头/模块）→ 再把角色包半身/全身 edit 进讲解位。  
3. **多参考合成**  
   同时传 clean + bust + sheet + 气质锁；身份以包图为准，气质锁不提供样例角色身份。  
4. **纯文案从零生成**  
   最容易漂发型/脸；仅当包图不可用时的退路，且必须更严审核。

气质锁 / 样例卡里的另一个角色（如示范 Ania）**永远不要**画进用户成品。

## 全身还是半身？（按排版决定，不默认某一种）

**没有「半身优先」或「全身优先」。** 每张卡在 shot list / visual plan 里写明 `CHARACTER CROP` 与理由：`none` | `bust` | `fullbody` | `multi-mini`。

选 **none（不出人）** 更合适时：

- 表格、流程、文件树、错对对照本身已经自洽  
- 强行塞人只会挡字或变装饰  

选 **半身 / 头胸** 更合适时：

- 文字模块多、需要大标题 + 多段说明  
- 角色主要靠表情、手势、手持物讲解  
- 全身会抢走信息区（参考信息密集的编辑样例）

选 **全身** 更合适时：

- 动作靠站姿/走位/推开某侧才能读懂（对比站位、递出 CTA）  
- 服装剪影本身是记忆点且本张信息模块较少  
- 版面下部或一侧专门留了全身讲解位且不压字

选 **多处分身（小）** 时：

- 步骤/对比需要同一角色出现在多个模块里  
- 每个分身更小，总面积仍不压过文字  

### 体量

- 字与模块是主角；角色服务讲解  
- 信息图页单次出场通常约占画面 **12%～22%**；只有需要站位演示时才放大，且不超过 28%
- 对比表、流程表、文件树等自洽页面优先 `character_budget: none`
- 禁止永远同一 pose（如永远抱电脑站右上角）  
- 禁止只贴一张人像在空白边当装饰  

## 互动（出场时必须）+ 职能测试

演示 / 讲解 / 对比 / 操作 / 递出结论，例如：捧 `SKILL.md` 并贴入第三步、拿清单检查第一块、把规则卡放进文件夹、连接两个流程节点、站在“对”的一侧。角色的手、道具或视线必须能指向一个具体文字模块。

**职能测试（出图前自问）：** 若去掉角色，箭头/模块/对白归属是否仍然完全成立？  
- 仍然完全成立 → 本张优先 `CHARACTER CROP: none`，或改成真正参与信息的动作  
- 会塌一块 → 保留角色，互动有效  

如果做不到指向具体模块，就去掉角色。

## Jinger-v2 发型裁决

若当前角色是 Jinger-v2，`character-bust.png` 是脸和发型的第一裁决源。统一称呼：**两侧垂落小侧马尾**——头顶左右两侧各用极少头发扎起，自然向下垂落，发尾柔软波浪并与下层深棕长波浪合流；上段桃粉/草莓金，发尾过渡棕黑。不是编辫子、短硬小揪、圆丸子、高双马尾或动物耳朵。出图后若发型不符合，即使版式和文字通过，也必须重绘。

## 与长文的区别

- 长文迷你剧场：角色常是戏的中心  
- 知识卡：信息架构是中心，角色是讲解员
